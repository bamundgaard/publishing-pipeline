# Key to the codes: <title>

The project files use short codes so agents can find things. This page says
in plain words what each one means. It changes no ruling; the full wording
of every ruling stays in `decision-ledger.md`.

Whoever adds a new code to the project adds its line here in the same run:
the planner adds units, the research assistant's ledger questions are added
when they are copied into the ledger, and the main session adds Ben's rulings
in short form after he rules. Never edit a ruling's meaning here.

## Source cards: SC-U03-12 and so on
A source card is a quoted excerpt from a registered source, kept in a unit's
dossier (`04-dossiers/`). SC-U03-12 means card 12 in the dossier for U03.
Drafts put card codes in brackets after the sentences they support.

Other brackets in drafts:
- [BT]: a quotation of the base translation.
- A ledger code such as [U03-D2] or [S13]: the sentence rests on Ben's ruling.

## Reviewer comments: TR2, SR7 and so on
| Letters | Reviewer | Reads for |
|---|---|---|
| TR | Tradition | Fit with the charter's tradition and boundaries |
| OR | Opposition | Whether other views get a fair hearing |
| SR | Scholar | Accuracy and use of the sources |
| PR | Preacher (or the genre's practitioner) | Usefulness to the reader |
| LR | Language | Greek and Hebrew forms and glosses |

Decisions on comments: "accept → stage 5" (the drafter fixes it), "accept →
stage 6" (the editor handles it), "reject" (no change).

## Editor's memo items
MF = must fix, SF = should fix, A = for the author. These are numbered within
each memo and are not ledger codes.

## Verification defects: VF1, VF2
In the verification logs (`08-verification/`), each failed check is a
defect numbered VF1, VF2, ... within that log. They are not ledger codes.

## Copyedit changes and queries: CE1, AQ1
In the copyedit change lists (`09-copyedit/`), CE1, CE2, ... are tracked
changes you can reject, and AQ1, AQ2, ... are questions for you. They are
numbered within each file and are not ledger codes.
